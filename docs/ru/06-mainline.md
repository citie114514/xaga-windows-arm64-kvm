## 2. Как это загружается (та же схема, что и в нашем проекте)

Автор объяснил подход в описании к видео. Примечательные моменты:

> Device tree засовывается в ядро, и ядро само его подменяет, потому что **правка dtbo ломает LK**.
> На раннем этапе отладка шла через зарезервированную область памяти (биты случайно переворачиваются,
> но после перезагрузки в Android это ещё можно прочитать). Позже, когда заработал драйвер UFS, kmsg
> писали в **пустой слот `vendor_boot_b`** и перепрошивались в Android, чтобы прочитать.
> Ещё позже, когда заработал simplefb, стало можно смотреть на экран напрямую. После того как поднялся
> USB, мы написали init вручную, чтобы USB отдавался как **serial console**, и с ПК можно было
> подключаться к `/dev/ttyACM0`. Наконец, rootfs был **прошит в `userdata` через fastboot**, смонтирован
> и запущен `/sbin/init`.

**Ключевые выводы**:

| Пункт | Подход |
|---|---|
| **Загрузчик** | **Сохранить штатный LK**, не портировать U-Boot (LK тоже умеет грузить mainline-ядро) |
| **Device tree** | **dtb встроен в ядро** и подменяется ядром (правка dtbo запрещена — иначе LK ломается) |
| **Ядро** | → раздел `boot` |
| **rootfs** | → раздел `userdata` (прошивается через fastboot) |
| **Отладка** | сначала зарезервированная память под kmsg → затем пустой слот `vendor_boot_b` → simplefb → USB-серийник |
| **Референс** | mt6878 mainline |

**Это тот же образ мысли, что и при включении KVM в Android**: сохранить LK, не трогать dtbo и
заменять только то, что можно заменить.

## 3. ⚠️ Ловушка, которую нужно знать: GEM Shrinker в Panthor 7.2

**Это напрямую связано с запуском виртуальных машин, обязательно прочитайте:**

> В panthor из Linux 7.2 появился **GEM Shrinker**, позволяющий освобождать память при её нехватке.
> **Но при слишком большой нагрузке на память накладные расходы на освобождение для panthor очень
> велики, и возникают громоподобные рывки.** В panthor 7.2 gem shrinker — первая версия чего-то
> нового, поэтому регрессии нормальны. **Если с этим столкнулись — пока просто отключите.**

Коммит с исправлением:
[`MT6895-Mainline/linux@4fadce8d`](https://github.com/MT6895-Mainline/linux/commit/4fadce8d6bbce016a8965ad93a5285c565401c1d)

**Почему это важно читателям нашего проекта**: **запуск виртуальной машины — это как раз сценарий
экстремального давления на память** (KDE + QEMU + несколько ГБ Windows + дисковый кэш).
Поэтому если на mainline Linux виртуальная машина тормозит непонятно почему — **сначала подозревайте
именно это**.

## 4. Почему mainline может ощущаться плавнее, чем Android

Из видео и информации о проекте видны несколько причин:

1. **Композитор KDE имеет полное GPU-ускорение** (Panthor/PanVK) — а графический стек Android в
   сценарии виртуальной машины, наоборот, мешает
2. **Нет вмешательства Android в фоне / термоконтроля / управления памятью**
3. **QEMU — обычная сборка из дистрибутива**, без всех адаптаций под Android, которые делает DroidVM
   (отсюда и проблемы, на которые мы наступали: путаница с портами VNC, перезапись `vms.json`,
   ограничения native-экспортёра)
4. Путь вывода может быть **локальным** (нативное окно / localhost VNC), с задержкой намного ниже,
   чем «проброс через adb на ПК, а потом ещё VNC сверху»

## 5. Как выбрать между двумя путями

| | **Android (этот проект)** | **Mainline Linux (эта страница)** |
|---|---|---|
| Объём доработок | Только прошить `tee_a` | Установить целую систему |
| Риск | Один раздел, откат возможен | Переразметка и прошивка rootfs |
| Повседневное использование | ✅ Можно звонить и пользоваться WeChat | ⚠️ Зависит от полноты порта |
| Опыт работы с ВМ | Работает, ограничен путём VNC | **Плавнее** (GPU-ускорение + локальный вывод) |
| Кому подходит | **Тем, кто хочет сохранить Android** | Тем, кто хочет использовать телефон как Linux-компьютер |

**Рекомендация**: сначала включите KVM на Android с помощью этого проекта (**этот шаг общий для обоих
путей** — в mainline нужна та же идея с ATF, только там ATF приходит из дистрибутива/проекта).
Когда станет комфортно, подумайте о переходе на mainline.
