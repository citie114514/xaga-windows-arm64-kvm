## 1. Запуск

```bash
# Выполняется на телефоне после копирования скрипта (нужен root)
adb shell su -c 'sh /data/local/tmp/boot-win.sh'
```

Скрипт жёстко закрепляет **VNC за портом 5900** и делает следующее:

```
[1] Убивает старые экземпляры (иначе порт занят и QEMU молча уходит на 5901)
[2] Ждёт, пока 5900 действительно освободится (до 30 с, потом сдаётся -- без компромиссов)
[3] Запускает QEMU (привязка к ядрам + полный набор настроенных флагов)
[4] Сверяет фактический порт прослушивания == 5900 (иначе завершается с ошибкой)
```

**Зачем сверять порт**: в `-vnc host:N` у QEMU `N` — это **номер display**, а порт равен `5900 + N`.
Если 5900 занят, **QEMU не выдаёт ошибку — он молча увеличивает номер display** → 5901 ✗
Поэтому скрипт обязан активно подождать, а потом сверить.

Остановка:

```bash
adb shell su -c 'sh /data/local/tmp/stop-vm.sh'   # короткое имя процесса, поэтому pkill -f не убьёт сам себя
```

## 2. Как увидеть экран (VNC)

```bash
adb forward tcp:5900 tcp:5900
# Любой VNC-клиент подключается к 127.0.0.1:5900 (без пароля)
```

Снятие кадров из командной строки (для скриншотов/отладки без клиента):

```bash
python scripts/vncgrab.py        # сохраняет vnc-0.png / vnc-1.png
python scripts/vncprobe.py       # измеряет реальную пропускную способность VNC
python scripts/vncinput.py       # отправляет одно нажатие, чтобы проверить реакцию гостя
```

**Для большей плавности**: в `boot-win.sh` уже включён `lossy=on` (сжатие JPEG с потерями);
измерения показали, что объём кадра падает с **3.00 MB до 0.36 MB (в 8.3 раза)**. Это самый большой выигрыш.

## 3. Разбор каждого флага QEMU

```bash
Q=/data/data/cn.classfun.droidvm/usr/bin/qemu-system-aarch64
FW=/data/data/cn.classfun.droidvm/usr/share/droidvm/aavmf-QEMU_EFI.fd
DISK=/data/media/0/DroidVM/win.vhdx

export LD_LIBRARY_PATH=/system/lib64        # <- обязательно! иначе пространство имён линковщика не найдёт системные библиотеки

taskset f0 "$Q" \                           # <- обязательно! привязка к кластеру A78, чтобы избежать гонки big.LITTLE
  -name win -L /data/data/cn.classfun.droidvm/usr/share/qemu \
  -accel kvm -machine virt -cpu host \
  -smp 4,sockets=1,cores=4,threads=1 -m 4096M \
  -bios "$FW" \
  -drive file="$DISK",if=none,id=nv0,format=vhdx,cache=writeback,aio=threads \
  -device virtio-blk-pci,drive=nv0,disable-legacy=on,disable-modern=off,bootindex=1 \
  -netdev user,id=n0 \
  -device virtio-net-pci,netdev=n0,disable-legacy=on,disable-modern=off \
  -device virtio-balloon-pci,disable-legacy=on,disable-modern=off \
  -device qemu-xhci,id=xhci \
  -device usb-tablet -device usb-kbd \
  -device virtio-gpu-pci,disable-legacy=on,disable-modern=off,xres=1920,yres=1080,edid=on \
  -vnc 127.0.0.1:0,lossy=on \
  -display none -nodefaults
```

| Флаг | Действие / примечания |
|---|---|
| `LD_LIBRARY_PATH=/system/lib64` | Нужен QEMU из DroidVM, иначе он не находит системные библиотеки |
| `taskset f0` | Привязка к CPU 4-7 (кластер A78). **Без неё он случайно падает** (см. приложение в [01-enable-kvm.md](01-enable-kvm.md)) |
| `-accel kvm` | Аппаратное ускорение (весь смысл прошивки `tee`). С `tcg` слишком медленно для работы |
| `-machine virt` | Универсальная виртуальная ARM-платформа |
| `-cpu host` | Проброс возможностей CPU хоста. **Обязательно вместе с taskset** |
| `-smp 4` | 4 vCPU. В телефоне 4×A78; **больше может попасть только на A55 и замедлит работу** |
| `-m 4096M` | 4 GB памяти. На телефоне не стоит превышать 4G |
| `-bios "$FW"` | **Обязательно штатный AAVMF** — модифицированная сборка из DroidVM крутится и зависает под QEMU |
| `-drive ... format=vhdx` | **QEMU читает и пишет VHDX напрямую** ✓ конвертация не нужна |
| `cache=writeback` | Компромисс. `cache=unsafe` быстрее (но рискует повреждением при отключении питания) |
| `aio=threads` | Асинхронный ввод-вывод через пул потоков (стабильнее, чем native на FUSE) |
| `if=none` + `-device` | Современный стиль: сначала объявить бэкенд, затем привязать его к устройству |
| `disable-legacy=on,disable-modern=off` | Только virtio 1.0 (modern). Драйверам Windows нужен modern |
| `bootindex=1` | Приоритет загрузки (AAVMF может его проигнорировать, но вреда нет) |
| `-netdev user,id=n0` | **Пользовательский NAT (slirp)** — именно он даёт ВМ выход в сеть |
| `-device virtio-net-pci` | Сетевая карта. Её драйвер — `NetKVM` (уже внедрён) |
| `-device virtio-balloon-pci` | Баллонная память. С установленным в госте `blnsvr` простаивающая память возвращается Android |
| `-device qemu-xhci,id=xhci` | USB-контроллер. **Обратите внимание: шина называется `xhci.0`, а не `xhci`** |
| `-device usb-tablet` | Мышь с абсолютными координатами (**не указывайте `bus=` и дайте подключиться автоматически**; `bus=usb` даёт ошибку) |
| `-vnc 127.0.0.1:0,lossy=on` | display 0 → порт **5900**; `lossy=on` включает сжатие JPEG |
| `-display none -nodefaults` | Без локального дисплея и без устройств по умолчанию (минимум = меньше ресурсов) |

### Необязательно: подключить диск с драйверами

```bash
if [ -f /data/local/tmp/virtio-win.iso ]; then
  set -- "$@" -drive file=/data/local/tmp/virtio-win.iso,if=none,id=cd0,media=cdrom,readonly=on \
              -device usb-storage,drive=cd0,removable=on
fi
```

> ✅ `virtio-win.iso` — это **чисто дисковый образ данных** (без El Torito и без EFI-загрузки),
> поэтому подключать его **безопасно**, он не перехватит загрузку.
> ❌ **Не подключайте установочный ISO Windows** — он загрузочный и будет конкурировать с системным диском.

## 4. Сеть

Скрипт запуска уже настраивает **пользовательский NAT QEMU (slirp)**:

| Пункт | Значение |
|---|---|
| IP виртуальной машины | `10.0.2.15` |
| Шлюз | `10.0.2.2` |
| DNS | `10.0.2.3` |
| Наружу | ✅ есть доступ в интернет |
| Внутрь | ❌ снаружи подключиться нельзя (свойство NAT) |

Драйвер — `NetKVM` (уже внедрён), поэтому **в Windows он работает без установки драйверов**.

**Убедиться, что сеть действительно работает** (посмотрите исходящие соединения QEMU с ПК):

```bash
adb shell su -c 'ss -tnp | grep qemu | grep -v 127.0.0.1'
# ESTAB  192.168.31.75:44394  ->  204.79.197.235:443      <- Microsoft
```

Внутри ВМ: если Edge открывает сайты — всё в порядке.

> **Подсказка**: если до входа в рабочий стол время выглядит абсурдно (например, 2768 год),
> **как только появится сеть, Windows NTP исправит это сам**.

## 5. Настройка производительности

### Измеренные данные (чтобы не гадать)

| Пункт | Измерено | Вывод |
|---|---|---|
| **VNC `lossy=on`** | на кадр **3.00 MB → 0.36 MB (в 8.3 раза)** | ✅ главный выигрыш, включать всегда |
| **Пропускная способность туннеля adb forward** | **276 MB/s** | ❌ **не узкое место**; не тратьте время на сеть |
| 1080p против 720p | в 2.25 раза больше пикселей | Влияет на стоимость рендера и кодирования |
| Привязка к ядрам | успех 2/5 → **3/3** | ✅ обязательно |

### Доступные ручки

| Хочется | Как |
|---|---|
| **Плавнее** | Снизить разрешение до 1280×720 (`xres=1280,yres=720`); отключить визуальные эффекты в Windows |
| **Меньше памяти** | Установить в госте `blnsvr.exe`, чтобы баллон возвращал простаивающую память Android |
| **Быстрее диск** | `cache=unsafe` (⚠️ при отключении питания файловая система может повредиться) |
| **Больше CPU** | **Не поднимайте `-smp` выше 4** — дальше потоки попадут на A55 и станет медленнее |
| **Больше памяти** | `-m` можно до 6G, но телефону тоже нужна память, и легко получить OOM |

### Настоящий ключ к плавности: путь вывода

```
Нативный локальный вывод (смотреть прямо на телефоне)  -> самый плавный
localhost VNC (петля на том же устройстве)             -> очень плавный
adb forward + VNC-клиент на ПК                         -> заметная задержка (вариант по умолчанию в проекте)
```

**Почему бывают рывки**: кодирование VNC в QEMU идёт в главном потоке, а `taskset f0` привязывает все
потоки к кластеру A78, поэтому поток VNC **конкурирует за те же 4 ядра** с четырьмя vCPU.

**Идеи, которые стоит попробовать** (в этом проекте полноценно не проверялись — отзывы приветствуются):

- Оставить одно ядро вспомогательным потокам QEMU: `-smp 3`
- `-cpu cortex-a78` (фиксированная модель CPU, без проброса хоста и гонки big.LITTLE) и отказаться от
  `taskset`, чтобы потоки QEMU разошлись по всем 8 ядрам

**На Android для ещё большей плавности**: используйте `native`-вывод приложения DroidVM
(он рисует прямо на экран телефона, вообще без сети — тот самый эффект «локально выглядит плавно»
из видео [kde-yyds](https://space.bilibili.com/2008726064)).

## 6. Ежедневное обслуживание

### Резервная копия / снимок

`win.vhdx` — это вся система Windows, поэтому **резервная копия обязательна**.

```bash
# Сделать сжатый снимок на телефоне (ВМ должна быть остановлена, иначе снимок будет рваным)
adb shell su -c 'export LD_LIBRARY_PATH=/system/lib64; \
  /data/data/cn.classfun.droidvm/usr/bin/qemu-img convert -c -o compression_type=zstd \
  /data/media/0/DroidVM/win.vhdx /data/local/tmp/win-snapshot.qcow2'
```

- **`-c` + zstd**: около 40 минут (упирается в CPU)
- **Без `-c`**: около 90 секунд, но файл примерно на 2 GB больше
- Результат можно использовать прямо как диск qcow2 (`format=qcow2`) или вернуть в vhdx через `qemu-img convert`

### Восстановление / замена диска

Верните образ резервной копии на место `win.vhdx`. Используйте `restore-disk.sh`, который:

1. Читает заголовок файла и **определяет формат** (VHDX / QCOW2 / VHD)
2. Сравнивает со свободным местом на `/data` и выдаёт ошибку, а не пишет половину файла
3. **Предупреждает перед перезаписью** существующей цели (3 секунды, Ctrl-C работает)
4. Считает **sha256** после копирования

```bash
adb push win.vhdx /data/local/tmp/
adb shell su -c 'sh /data/local/tmp/restore-disk.sh /data/local/tmp/win.vhdx'
```

> ⚠️ **Не делайте** просто `adb push win.vhdx /data/media/0/DroidVM/` —
> у обычных прав adb нет доступа на запись в этот каталог (он только для root), и вы получите
> `permission denied`. Сначала скопируйте в `/data/local/tmp`, затем переместите под root.
> `restore-disk.sh` уже это учитывает.

**Если диск в формате QCOW2** (например, при восстановлении из сжатого снимка выше), не забудьте
заменить в `boot-win.sh` `format=vhdx` на `format=qcow2`, иначе QEMU откажется его открывать.

### Проверка текущего состояния

```bash
# Что-нибудь запущено?
adb shell su -c 'pgrep qemu-system-aar | wc -l'

# VNC на 5900?
adb shell su -c 'netstat -tln | grep 5900'

# Последний лог запуска (и аргументы, и ошибки здесь)
adb shell su -c 'tail -40 /data/local/tmp/win-qemu.log'

# Лог последовательного порта (ранняя загрузка Windows видна здесь)
adb shell su -c 'tail -40 /data/local/tmp/win-serial.log'
```

### Место

Системный диск в реальной работе вырастает примерно до **~23 GB** (динамический диск на 100 GiB).
С учётом резервной копии держите на телефоне в `/data` свободными хотя бы **40 GB**.

```bash
adb shell su -c 'df -h /data | tail -1'
```
