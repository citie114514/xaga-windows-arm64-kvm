## 2. 起動方法（本プロジェクトと同じ発想）

作者は動画の概要欄でやり方を説明しています —— 注目すべき点：

> デバイスツリーはカーネルに詰め込んでカーネル自身に差し替えさせる。**dtbo を変更すると LK が壊れる**から。
> 初期のデバッグは予約メモリ領域に頼った（ビットはランダムに反転するが、Android に再起動すれば
> まだ読めた）。後に UFS ドライバが動いたので、kmsg を**空きスロットの `vendor_boot_b` パーティション**
> に書き、Android に焼き戻して読んだ。さらに simplefb が動けば画面を直接見られる。
> USB が動いた後は init を自作し、USB を **serial console** として公開して PC から `/dev/ttyACM0` に
> 直接接続した。最後に rootfs を **fastboot で `userdata` に焼き込み**、マウントして `/sbin/init` を起動。

**重要な結論**：

| 項目 | やり方 |
|---|---|
| **ブートローダー** | **純正 LK を維持**、U-Boot には移植しない（LK でもメインラインカーネルをロードできる） |
| **デバイスツリー** | **dtb をカーネルに埋め込み**、カーネル自身に差し替えさせる（dtbo は変更不可。変更すると LK が壊れる） |
| **カーネル** | → `boot` パーティション |
| **rootfs** | → `userdata` パーティション（fastboot で書き込み） |
| **デバッグ** | 初期は予約メモリに kmsg → 後に `vendor_boot_b` の空きスロット → simplefb → USB シリアル |
| **参考** | mt6878 mainline |

**これは Android 上で KVM をやる際と同じ発想です**：LK を残し、dtbo に触れず、差し替えられる
部分だけを差し替える。

## 3. ⚠️ 必ず知っておくべき罠：7.2 Panthor の GEM Shrinker

**これは「仮想マシンを動かす」に直結するので必ず読んでください：**

> Linux 7.2 の panthor は **GEM Shrinker** を導入し、空きメモリが少ないときにメモリ回収を行えます。
> **しかしメモリ負荷が大きすぎると、回収が panthor に与えるコストが非常に大きく、雷のような大カクつき
> が発生します。** 7.2 の panthor では gem shrinker は新規導入の最初のバージョンなので、回帰が
> 出るのも自然です。**遭遇したらまず切ってください。**

修正コミット：
[`MT6895-Mainline/linux@4fadce8d`](https://github.com/MT6895-Mainline/linux/commit/4fadce8d6bbce016a8965ad93a5285c565401c1d)

**なぜ本プロジェクトの読者に関係するか**：**仮想マシンの実行はまさに「メモリ負荷が極大」の
シナリオ**です（KDE + QEMU + Windows の数 GB + ディスクキャッシュ）。
したがってメインライン Linux 上で仮想マシンが妙にカクつくなら、**まずこれを疑ってください**。

## 4. なぜメインラインの方が Android より滑らかになるのか

動画とプロジェクトの情報からいくつか理由が見えます：

1. **KDE のコンポジタが完全な GPU 加速を持つ**（Panthor/PanVK）—— Android のグラフィックススタックは
   仮想マシンのシナリオではむしろ回り道になる
2. **Android のバックグラウンド/温調/メモリ管理の干渉が無い**
3. **QEMU がディストリビューションの通常ビルド**で済む —— DroidVM のように Android 向けの各種適応が
   不要（本プロジェクトが踏んだ VNC ポートのズレ、`vms.json` の書き換え、native exporter の制約
   といった問題が起きない）
4. 表示経路を**本機**にできる（ネイティブウィンドウ / localhost VNC）。「adb 転送で PC に送って
   そこから VNC」より遥かに低遅延

## 5. 2 つの道の選び方

| | **Android（本プロジェクト）** | **メインライン Linux（本稿）** |
|---|---|---|
| 改造量 | `tee_a` を焼くだけ | システム全体を入れる |
| リスク | 1 パーティションのみ、ロールバック可能 | 再パーティション + rootfs 書き込み |
| 日常の主力 | ✅ 電話も WeChat も使える | ⚠️ 移植の完成度次第 |
| 仮想マシンの体験 | 使えるが VNC 経路に制約される | **より滑らか**（GPU 加速 + 本機表示） |
| 向いている人 | **Android を残したい人** | この端末を Linux マシンとして使いたい人 |

**推奨**：まず本プロジェクトで Android 上に KVM を通してください（**この段階は両路線で共通**です ——
メインラインでも同じ ATF の原理が必要で、違うのはメインラインの ATF がディストリビューション/
プロジェクトから提供される点だけ）。快適に使えたら、メインラインを検討してください。
