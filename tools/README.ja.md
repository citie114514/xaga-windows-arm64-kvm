# 新しいファームウェア向けに profile を特定するツール

[中文](README.md) | [English](README.en.md) | **日本語** | [Русский](README.ru.md)

すでに profile はあるがファームウェアのバッチが違うデバイス向けに、**オフセットを再特定**する
ためのツール群です。核心となる考え方：**バイトをずらして当て推量するのではなく、
旧 profile の既知の位置にある「命令の骨組み」を新しいバイナリ内で検索する。**

## スクリプト

| スクリプト | 役割 |
|---|---|
| `find-new-offsets.py` | 旧 profile の各フィールド位置の 16 バイト命令列を指紋として**新しい ATF** 内で検索し、2 つの ATF のブロック単位の類似度分布も出力する |
| `find-getter.py` | 旧/新 ATF の getter 領域を逆アセンブルし、`0xD00001A8` のようなアンカーの前後を 1 つずつ確認する |
| `match-lk2.py` | **主力ツール**：LK を一度線形逆アセンブルし、`bl`/`adrp` などの PC 相対オペランドを**正規化**してプレースホルダに置き換え、命令の骨組みをスライディングウィンドウで比較する。「関数が動くと `bl` のエンコードが変わり、バイト指紋が全滅する」罠を回避できる |
| `find-lk-offsets.py` | 初期版（バイト単位の指紋）。比較用に残している —— *なぜ失敗するのか* が教材になる |
| `verify-patch-diff.py` | NoGZ パッチのオフライン検証：あるパッチとそのベースとの差分領域を、すでに実機検証済みのパッチと比較し、同じパイプラインから出たものか（同型か）を確認する |

## 実戦の流れ（今回まさにこの手順、約 1〜2 時間）

```
1) デバイスから新しいファームウェアを dump：tee_a / lk_a / preloader_raw_a
2) tee から ATF メンバを取り出す（オフセット 0x200、長さ 283016）
3) find-new-offsets.py を実行：
     旧 profile の各フィールド → 新しい ATF 内で 16 バイト指紋を検索
     ヒットかつオフセットが近い（±0x100）→ そのまま採用
4) match-lk2.py を実行：すべての lk_* オフセットを特定
5) 結果を新しい profile として書き出し、ハッシュを新しくして profiles.json にマージ
6) build.py --check-only を実行 → 14/14 であること
7) 完全ビルドを実行（--preloader + --tools）→ 署名検証が 2 × Result: VALID であること
```

## 今回の実測データ（Redmi Note 11T Pro+、2 つのファームウェアバッチ）

**ATF**：新しいファームウェアのオフセットは上流 `xaga` と**完全一致**（7 箇所の正確なヒット）——
2 つの ATF はバイト単位では **29.5% しか一致しない**のに（別ビルドだが**関数レイアウトは同一**）。

**LK**：バイト単位で **83.86% 一致**。11 個のフィールドのうち：

```
9 個はオフセット不変   0x28D4 / 0x2904 / 0x39C8 / 0x3A6C / 0x1A7A0 / 0x1A7CC / 0x3A18 / 0x14CAC / 0x14D40
2 個が −0x90 シフト    lk_getter   0x1E8A8 → 0x1E818
                       lk_callback 0x1E8BC → 0x1E82C
```

## 踏んだ罠

| 罠 | 説明 |
|---|---|
| **LK ではバイト指紋が全滅する** | `bl`/`adrp` は PC 相対なので、関数が動けばエンコードが変わる → **命令の骨組みを正規化**してから比較する必要がある（`match-lk2.py` がまさにそれ） |
| **`md.skipdata = True` は必須** | LK ファイルの先頭はコードではなくヘッダ。このフラグが無いと Capstone が即座に停止する（命令が 1 個しか出ない ✗） |
| **profile の値は文字列でなければならない** | `build.py` は `int(v, 0) if v.startswith("0x")` を行う → 整数で書くと `AttributeError` ✗ |
| **上流の `sign_all_flag` バグ** | `build.py` は `sign_mtk_cert.py` に `--all` を渡すが、あちらのスクリプトにその引数は無い → `sign_all_flag()` が `[]` を返すようにする必要がある（[issues/](../issues/) 参照） |
