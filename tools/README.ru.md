# Инструменты для определения profile под новую прошивку

[中文](README.md) | [English](README.en.md) | [日本語](README.ja.md) | **Русский**

Для устройств, у которых профиль уже есть, но партия прошивки другая — эти инструменты
**заново находят смещения**. Основная идея: **не угадывать, сдвигая байты, а искать в новом
бинарнике «скелет инструкций», известный по позициям старого профиля.**

## Скрипты

| Скрипт | Назначение |
|---|---|
| `find-new-offsets.py` | Использует 16-байтовую последовательность инструкций в каждом поле старого профиля как отпечаток, ищет её в **новом ATF** и выводит распределение похожести двух сборок ATF по блокам |
| `find-getter.py` | Дизассемблирует область getter старого/нового ATF, чтобы по одному просмотреть контекст вокруг якорей вроде `0xD00001A8` |
| `match-lk2.py` | **Рабочая лошадка**: один раз линейно дизассемблирует LK, **нормализует** PC-относительные операнды (`bl`, `adrp`, …) в заполнители, а затем сравнивает скелеты инструкций скользящим окном. Так обходится ловушка, когда функция сдвигается, кодировка `bl` меняется и все байтовые отпечатки становятся бесполезны |
| `find-lk-offsets.py` | Ранняя версия (байтовые отпечатки), оставлена для сравнения — *почему* она не работает, поучительно |
| `verify-patch-diff.py` | Офлайн-проверка патча NoGZ: сравнивает области различий патча и его базы с таковыми у уже проверенного на железе патча, чтобы подтвердить, что оба вышли из одного конвейера («изоморфизм») |

## Реальный процесс (именно так мы и делали, около 1–2 часов)

```
1) Снять новую прошивку с устройства: tee_a / lk_a / preloader_raw_a
2) Извлечь член ATF из tee (смещение 0x200, длина 283016)
3) Запустить find-new-offsets.py:
     каждое поле старого профиля -> искать его 16-байтовый отпечаток в новом ATF
     попадание И близкое смещение (±0x100) -> принять как есть
4) Запустить match-lk2.py: найти все смещения lk_*
5) Записать результат как новый профиль, подставить новые хеши, слить в profiles.json
6) Запустить build.py --check-only -> должно быть 14/14
7) Запустить полную сборку (--preloader + --tools) -> проверка подписи должна дать 2 × Result: VALID
```

## Фактические данные этого проекта (Redmi Note 11T Pro+, две партии прошивки)

**ATF**: смещения новой прошивки **полностью совпадают с апстримом `xaga`** (7 точных попаданий) —
хотя два ATF совпадают побайтово лишь на **29.5%** (разные сборки, но **структура функций одинакова**).

**LK**: побайтовое совпадение **83.86%**; из 11 полей:

```
9 смещений без изменений   0x28D4 / 0x2904 / 0x39C8 / 0x3A6C / 0x1A7A0 / 0x1A7CC / 0x3A18 / 0x14CAC / 0x14D40
2 сдвинуты на −0x90        lk_getter   0x1E8A8 -> 0x1E818
                           lk_callback 0x1E8BC -> 0x1E82C
```

## Ловушки, которые мы прошли

| Ловушка | Пояснение |
|---|---|
| **Байтовые отпечатки на LK бесполезны** | `bl`/`adrp` — PC-относительные, поэтому при сдвиге функции кодировка меняется → нужно **нормализовать скелет инструкций**, и только потом сравнивать (этим и занимается `match-lk2.py`) |
| **`md.skipdata = True` обязателен** | Файл LK начинается с заголовка, а не с кода; без этого флага Capstone останавливается сразу (дизассемблируется ровно 1 инструкция ✗) |
| **Значения в профиле должны быть строками** | В `build.py` есть `int(v, 0) if v.startswith("0x")` → целое число вызовет `AttributeError` ✗ |
| **Баг `sign_all_flag` в апстриме** | `build.py` передаёт `--all` в `sign_mtk_cert.py`, но в том скрипте такого аргумента нет → `sign_all_flag()` должен возвращать `[]` (см. [issues/](../issues/)) |
