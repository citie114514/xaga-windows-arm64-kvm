# Скрипты для телефона

[中文](README.md) | [English](README.en.md) | [日本語](README.ja.md) | **Русский**

Закиньте их в `/data/local/tmp/` на телефоне и запускайте там. **Всем им нужен root.**

| Скрипт | Что делает | Проверен |
|---|---|---|
| [`boot-win.sh`](boot-win.sh) | Запускает QEMU + KVM (**жёстко привязывает VNC к 5900**, понятно сообщает, если диск отсутствует) | ✅ |
| [`stop-vm.sh`](stop-vm.sh) | Безопасно останавливает (сопоставление по короткому имени процесса, поэтому `pkill -f` не убьёт вашу же оболочку) | ✅ |
| [`restore-disk.sh`](restore-disk.sh) | Возвращает сохранённый виртуальный диск на место `win.vhdx` (определяет формат / проверяет свободное место / сверяет sha256) | ✅ |
| [`qemu-wrapper.sh`](qemu-wrapper.sh) | **Необязательно**: обёртка вокруг QEMU для DroidVM, чтобы работали и конфиги самого приложения | ✅ |

## Установка

```bash
adb push scripts/phone/boot-win.sh scripts/phone/stop-vm.sh scripts/phone/restore-disk.sh /data/local/tmp/
adb shell su -c 'chmod 755 /data/local/tmp/*.sh'
```

# Два пути запуска — **выберите один, не смешивайте**

## Путь A: запуск из командной строки (**рекомендуется**)

```bash
adb shell su -c 'sh /data/local/tmp/boot-win.sh'
adb forward tcp:5900 tcp:5900
# VNC-клиент подключается к 127.0.0.1:5900
```

| Плюсы | Минусы |
|---|---|
| Аргументы **полностью под контролем**; порт **жёстко 5900**; не зависит от DroidVM | Нет графического интерфейса; менять аргументы — править скрипт |

**Этот путь полностью обходит управление конфигурацией DroidVM** — он не читает
`vms.json`, и приложение не может его переписать.

## Путь B: чтобы приложение DroidVM тоже могло запускать (необязательно)

Конфигурации, которые создаёт приложение DroidVM, **сами по себе не работают**: оно не
подключает бэкенд `-netdev` к virtio-сетевой карте (у гостя нет сети) и не добавляет
`virtio-balloon` (память только растёт).

Это исправляет **скрипт-обёртка** — подмените `qemu-system-aarch64`, который вызывает
приложение, на обёртку, перенаправляющую вызов настоящему `.real`:

```bash
# 1) Сначала переименуйте исходный бинарник (один раз)
adb shell su -c 'cd /data/data/cn.classfun.droidvm/usr/bin && \
                 [ -f qemu-system-aarch64.real ] || mv qemu-system-aarch64 qemu-system-aarch64.real'

# 2) Закиньте обёртку
adb push scripts/phone/qemu-wrapper.sh /data/local/tmp/
adb shell su -c 'cp /data/local/tmp/qemu-wrapper.sh /data/data/cn.classfun.droidvm/usr/bin/qemu-system-aarch64'

# 3) Приведите права и владельца в соответствие с .real
adb shell su -c 'cd /data/data/cn.classfun.droidvm/usr/bin && \
                 chmod 755 qemu-system-aarch64 && \
                 chown $(stat -c %u qemu-system-aarch64.real):$(stat -c %g qemu-system-aarch64.real) qemu-system-aarch64 && \
                 ls -l qemu-system-aarch64*'
```

Она делает три вещи и **только если вызывающая сторона их не задала**, поэтому пути A
она не мешает:

```
1) Пишет полный список аргументов в /data/local/tmp/qemu-args.log   <- очень полезно при отладке
2) Добавляет -netdev user, если его нет (id auto0, чтобы не столкнуться с id вызывающего)
   Добавляет virtio-balloon-pci, если его нет
3) Привязывает всё к кластеру A78 через taskset f0 -- обходит гонку миграции big.LITTLE,
   которая ломает KVM
```

**Откат**: верните `.real` на прежнее имя.

# ⚠️ Три ловушки приложения DroidVM

## 1. Порт VNC по умолчанию **случайный**

`screens.*.vnc.port` в `vms.json` по умолчанию равен **`-1`**, то есть «выбрать автоматически»:

```json
"vnc": { "host": "127.0.0.1", "port": -1, "password": "", "password_auth": false }
```

**Следствие**: порт может отличаться при каждом запуске ✗ — то, что вы пробросили через
`adb forward tcp:5900`, никто не слушает ✗. Это частая причина «ВМ явно работает, но
подключиться не удаётся».

- **Что делает этот проект**: путь A прописывает `-vnc 127.0.0.1:0` (то есть 5900) и
  после запуска перепроверяет фактический порт
- Задать поле `port` теоретически тоже можно, но это **не проверено** и несёт риск из
  пункта 3 — **не рекомендуется**

## 2. Конфигурации, создаваемые приложением, неполны

См. «Путь B» выше — в них нет `-netdev` и balloon, их добавляет обёртка.

## 3. Правка `vms.json` вручную ломает чтение в приложении

**Симптом**: вы правите `vms.json` руками (например, меняете путь к диску), и ВМ **просто
исчезает** из приложения с ошибкой «текущая версия не может это прочитать».

**Причина**: DroidVM проверяет по собственной строгой схеме и **не знает добавленных
вручную полей**, поэтому выбрасывает запись целиком.

**Решение**
- **Меняйте только уже существующие поля** (например `disks[].path`, `screens.*.exporter`) — **никогда не добавляйте новые**
- Сохраняйте исходного владельца и права:
  ```bash
  OWN=$(stat -c %u vms.json); GRP=$(stat -c %g vms.json); MODE=$(stat -c %a vms.json)
  # ... правка ...
  chown $OWN:$GRP vms.json; chmod $MODE vms.json
  ```
- **Сначала сделайте копию**: `cp vms.json vms.json.bak`

> Остальные ловушки — в [docs/05-gotchas.md](../../docs/05-gotchas.md) (пункты 2 и 9).
